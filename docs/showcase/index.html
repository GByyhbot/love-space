Features

覆盖一对情侣日常记录的全部场景，含 2.7.x 新增的音乐、一起看与 2.8.0 已发布的定位守护与情侣报备。点击左侧卡片，右侧会展开该模块的完整能力清单——内容以项目档案为准，截至 2026-11-24 晚 2.8.0 发版状态。

Architecture

架构：轻量，但该有的都有

后端单体 FastAPI + SQLite，Web 端原生 JS，手机端 Flutter 一套代码覆盖 Android + iOS（Capacitor 旧壳已退役）；部署靠 Docker 镜像，NAS 上只拉取不编译。

后端 BACKEND

FastAPI + SQLite

Python 单体服务，数据全在一个目录里，备份迁移就是打包一个文件夹。

  • app/ — API、媒体处理、定时 Worker
  • love.db 主库 + period.db 生理期独立库
  • SSE 实时事件推送 /api/events
  • SelectiveGZip：静态与 JSON 压缩，SSE / 视频流原样直出保 Range
  • 媒体转码、每日备份、通知投递由内置 Worker 驱动
客户端 CLIENT

Web 原生 JS + Flutter App

Web 无框架拆分 bundle；App 已全面迁移 Flutter，后端接口零改动复用。

  • watch.js 一起看 · chat.js 私聊 · music.js 歌单 · period.js 生理期 · app.js 核心
  • Flutter：五 Tab + Dock 上滑「记录此刻」抽屉，二级页统一 context.push
  • 鉴权纯 Cookie love_session（30 天），写接口需 X-Love-Space: 1
  • 实时走 SSE /api/events，聊天以 client_id 去重
  • 媒体按区隔离：chat/ timeline/ music/ private/ space/ inbox/ 分月存放
交付 DELIVERY

Docker + Flutter APK

GitHub Actions 构建镜像与 APK；版本名由 versionCode 推导，镜像执行二标制。

  • 镜像二标制：每源仅 latest + 当前版本（GHCR 与 Docker Hub 各一份）
  • NAS 拉取：GHCR 直连首选，不可达时 Hub 按 digest 强拉同一产物；禁用 Hub latest
  • 版本镜像规则：当前 VC 280 ↔ 2.8.0（已发布）；版本名恒由 versionCode 推导
  • 验真以 /api/status 的 build 号为准，不以本机 image ID 为准
访问路径：手机 / 浏览器→ HTTPS →Nginx / Caddy 反代→ 127.0.0.1:1314 →love-space 容器→/data 持久化目录
Deploy

部署：只需要两个文件

运行只需要 docker-compose.yml 和 .env——镜像由 GitHub Actions 构建好推到 GHCR，服务器 / NAS 上不编译源码。

Terminal
# 1. 建目录，放上仓库根目录的 docker-compose.yml
mkdir -p /vol1/1000/LARJ && cd /vol1/1000/LARJ

# 2. 首次初始化设置一次性随机口令
echo "SETUP_TOKEN=<随机口令>" >> .env

# 3. 拉镜像并启动（数据目录 ./data 自动创建）
docker compose pull
docker compose up -d

# 4. 查看状态
docker compose ps
curl http://127.0.0.1:1314/health

初始化三步

  • 第一个账号在页面完成初始化（需输入 SETUP_TOKEN）
  • 初始化完成后从 .env 删除 SETUP_TOKEN 并重启容器
  • 首页点「发送邀请」生成链接给另一半注册；双方绑定后注册自动关闭
⚠️ 镜像口径已定（2026-11-19 / 11-23 补充）：NAS 首选 GHCR 直连 ghcr.io/gbyyhbot/love-space；GHCR 不可达时，从 Docker Hub 按 digest 强拉同一 CI 产物并本地 retag。禁用 Hub latest，不用南大代理（缓存旧 manifest）。回执 digest 必须以注册表回读为准。
Caddyfile · 自动 HTTPS
love.example.com {
    reverse_proxy 127.0.0.1:1314
}

# .env 中设置：
# PUBLIC_URL=https://love.example.com
# SECURE_COOKIES=true（默认开启）

云服务器要点

  • 域名解析到服务器，Nginx / Caddy 反代到容器 1314 端口并配证书
  • 防火墙只放行 80 / 443；应用端口默认仅监听本机 127.0.0.1:1314
  • 每日自动备份在 data/backups/ 保留 7 份，可设 BACKUP_EXTRA_DIR 异地再存一份
  • 升级：改 .env 的 LOVE_IMAGE 到目标 tag 后 docker compose pull && up -d，数据目录不受影响
恢复与迁移
# 手动完整备份
docker exec love-space python -m app.manage backup

# 导出备份包（含 love.db 与 period.db）
docker cp love-space:/data/backups/backup-XXXX.zip .

# 恢复到新目录（目标必须是新的空目录）
docker run --rm -v /vol1/1000:/target -v $PWD:/src 镜像名 \
  python -m app.manage restore /src/backup-XXXX.zip /target/LARJ-new

NAS 部署注意

  • 会话 Cookie 默认要求 HTTPS；用 NAS IP 访问会跳转到 PUBLIC_URL 域名
  • 数据目录放 NAS 共享卷，随快照 / RAID 一起保护
  • 网页录音需要 HTTPS：可用 NAS 反向域名或自签证书 + Tailscale / WireGuard
  • iPhone 网页通知需 iOS 16.4+ 先「添加到主屏幕」再开启
  • 远程访问建议走 Tailscale / VPN，避免直接暴露公网；恢复后所有登录会话与待发通知会被安全重置
本地开发
python -m venv .venv && . .venv/bin/activate
pip install -r requirements-dev.txt
uvicorn app.main:app --reload --port 8000
pytest   # API 验收 + 媒体链路 + 安全 + 版本一致性

两条铁律

  • 改前端必须同时改两个版本号：static/sw.js 的 VERSION 与 static/index.html 全部 ?v= 必须同号，否则用户会拿到「新 JS + 旧 CSS」
  • 网页版本号从 git tag 来：发版只需 git tag v1.2.5 && git push --tags，镜像版本号自动生成，不要手改代码
  • 发版前照 docs/真机验收.md 在真机走一遍——干净库的冒烟测试覆盖不到历史数据渲染等分支

关键环境变量

全部配置走 .env，数据目录必须持久化。

DATA_DIR /data

主库、生理期独立库、媒体、备份、密钥，必须持久化

SETUP_TOKEN 空

首次远程初始化一次性口令，用完即删

PUBLIC_URL 空

对外访问地址，用于通知跳转链接与来源校验

SECURE_COOKIES true

会话 Cookie 仅通过 HTTPS 发送，生产保持开启

LOVE_BIND_ADDRESS 127.0.0.1

宿主机监听地址，只允许同机反向代理连接

MAX_UPLOAD_MB 250

单文件上传上限

BACKUP_PASSWORD 空

设置后新备份使用 AES-GCM 加密，忘记无法恢复

RUN_WORKER true

内置定时任务：媒体转码、备份、通知投递

Security & Privacy

安全与隐私：私密是默认，不是选项

这是给两个人存最私密记录的地方，所以从加密、权限到通知文案，每一层都按「对方和外人都看不到」来设计。

🔐

正文加密落库

私密日记、草稿、未公开惊喜的正文以 AES-GCM 加密存储，且不出现在对方的页面、搜索、相册、通知和导出中——完全账号隔离。

🗝

密钥与密码

渠道密钥用 Fernet 加密存储；密码使用 scrypt 哈希；登录 / 注册有频率限制；备份文件权限 600，可再加 BACKUP_PASSWORD 加密。

🛡

访问控制

未登录无法访问任何 API 与媒体文件，所有媒体经权限校验后流式返回；外发通知地址强制 HTTPS 与公网校验，防 SSRF。

📵

通知不泄密

通知仅发送摘要、不含正文；Android 锁屏仅显示通用提醒；退出登录时清除本机草稿与推送订阅。

💾

数据保障

每日自动备份保留 7 份，支持手动备份、个人数据导出、完整恢复与迁移；导出仅包含本人有权查看的内容。

📦

资源防护

聊天 ZIP 导入限制压缩包 50MB、解压总量 100MB、单条目 30MB、图片 2000 张，避免异常压缩包耗尽资源。
