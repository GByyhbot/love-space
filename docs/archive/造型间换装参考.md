# 造型间 · 换装参考项目（为扩充衣物做准备）

> 目的：评估 GitHub 上换装 / 动漫头像类开源项目，挑出对「恋爱空间 造型间」扩充衣物真正有用的思路。
> 结论先说：**你贴的两个仓库是 2D / 云端 GPU 管线，无法直接用于本地离线的 3D 程序化造型间；真正对口的是「参数化 3D 换装」这一类（GarmentCode / symbios-avatar / SMPL·VRM 衣物资产）。**

---

## 一、你贴的两个仓库：是什么、能用什么

### 1. SwimmingLiu/TryonandAnimeAvatar
- **本质**：微信小程序的 **2D 虚拟换装 + 照片动漫化**。
  - 换装 = **HR-VITON**（人物图 + 衣服图 → 合成图，图像级 warp/扩散，不是 3D）。
  - 动漫头像 = **AnimeGANv3**（真人照片 → 动漫风格迁移）。
- 架构：Flask + MySQL + 模型端（PoseNet / Graphonomy / DensePose / HR-VITON）。
- **与造型间的关系**：❌ 无 3D 身体、无衣物网格、无模块化衣物系统。**代码不可移植**。
- ✅ **唯一可借鉴**：换装页的「模特轮播 + 预设服饰列表 + 历史记录」这种 **目录式 UX**（目前造型间已有类似的 GARMENTS 表 + 网格 UI，可参考它做得更丰富：分类 Tab、收藏、搜索）。

### 2. airen3339/ai-fashion-agent
- **本质**：**视频**级 AI 换装智能体（原视频 + 人物图 + 衣服图 → 换装视频）。
  - 模型：**CatVTON / IDM-VTON**（扩散换装）+ **InstantID**（身份保持）。
  - 三层架构：Vue3 + Spring Boot + FastAPI Worker；MySQL/Redis/MinIO。
- **代价**：需下载 ~30GB 权重 + 至少一张 RTX 4090；30s 720P 视频约 10 分钟。
- **与造型间的关系**：❌ 同样是 2D 视频，且依赖云端 GPU。
- ⚠️ **许可证红线**：CatVTON / IDM-VTON 是 **CC BY-NC-SA 4.0（非商用）**；本项目此前已决定不做真人 AI 试衣（与「数据只在 NAS 上」第一性原则冲突）。**不要引入。**

> 这两个仓库的共同标签：**AI 图像/视频生成、云端、GPU、非商用许可**。和「本地 3D、零 API、离线」完全相反。可学 UI，不可学内核。

## 二、真正对口的参考系：参数化 3D 换装

顺着「anime avatar / parametric clothing」搜到的这一类才是正解。核心思想来自 `symbios-avatar` 的设计文档（与造型间现状高度吻合）：

| 思想 | 原文要点 | 对应造型间现状 |
|---|---|---|
| **身体是程序化的** | 参数向量 → 骨架 → 在几何体上生成网格 → 解析求蒙皮权重 → 一次性 LBS | 已是：`BODIES` 表 + `latheMesh/limb/shell` 程序化生成 |
| **紧身衣物 = 身体表面 +ε，被覆盖区压制** | "Tight clothing is the body surface re-evaluated at +ε" | 已是：`latheMesh(profile, z=clothZ)` 在身体外裹一层 |
| **宽松衣物 = 从身体环扫出的面板** | "Loose garments are swept panels from body rings (GarmentCode's component taxonomy)" | 部分有：`skirt` 用 lathe 扫出，但还没抽象成「组件」 |
| **服饰不需要布料模拟** | "Dress needs no cages and no cloth sim" | 已是：无 cloth sim，靠骨骼 IK |
| **质感 70% 靠纹理而非着色器** | "~70% textures, not shaders: painted bevels + baked AO… no outlines" | 缺：目前几乎纯色 + 简单光照，缺织物纹理/烘焙 AO |
| **少量可蒙皮网格 + LOD** | "one draw per skinned mesh, 15–30k tris, quality tiers" | 体型极轻（顶点少），但还没分层 LOD |

另两个可留意的关键词（按需深入）：
- **GarmentCode**：把衣物拆成「组件 + 参数」（领口、袖子、裙摆、下摆…）的 3D 衣物 DSL。是「衣物=数据而非新几何体」的最佳范本。
- **SOMA-X / SMPL-X**：NVIDIA 的统一参数化人体（Apache-2.0），以及标准的 SMPL 系列。若未来想引入现成 3D 人体/衣物资产，SMPL 拓扑是事实标准；但 SMPL 本体是非商用，**只作设计参考，不引模型权**。

## 三、给造型间扩充衣物的落地方案（建议）

保持现有「本地 3D、零 API、离线」路线不变，按下面四步把衣物从「硬编码分支」变成「可配置组件」：

1. **紧身 / 宽松 双轨制**（已在用，需显式命名）
   - `tight`：在身体表面 +ε 偏移生成（T 恤、衬衫、裤子、裙子当前都是这类）。
   - `loose`：从身体横截面环「扫出面片」（披风、连衣裙大裙摆、斗篷、宽腿裤）。

2. **把 GARMENTS 从「逐件 if 分支」重构为「组件列表」**
   - 一件衣服 = `[bodice(环), sleeve(左/右, 长/短), collar(翻领/圆领), hem, skirtSweep(弧度/长度/开叉)]`。
   - 加新衣服 = 加一行数据（带参），不再写新的 `if (g.kind === 'xxx')` 分支。
   - 参考 GarmentCode 的组件化思路，但**保持程序化生成**（不引入外部 GLB 依赖）。

3. **纹理驱动质感（补短板、性价比最高）**——直接对应「达到换装游戏水平」
   - 共享一张程序化「织物纹理」（针织、牛仔斜纹、蕾丝、皮革）按衣物 tint 着色。
   - 烘焙一份 AO / 接触阴影贴图（腋下、领口、裙摆内侧），伪立体感立刻上来。
   - 仍不用描边（现有约定：眼睛/腮红/高光/头发不加反向外壳）；走 MeshStandard 的 roughness/normal。

4. **未来可选：GLB/VRM 衣物资产**
   - 若想要「写实褶皱」级衣物，可引入 VRM 的 humanoid-only 衣物资产或自建 GLB，**但这是大工程**，且会破坏离线轻量原则。建议先走 1–3。
