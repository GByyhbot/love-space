# 真机验收（Android）

> 给前端改动做一次「真实数据 + 真实 WebView」的抽检。
> 自动化冒烟（`tests/e2e/smoke.py`）跑的是**干净库**，只能覆盖主路径；
> 这里补的是它测不到的分支：历史数据渲染、跨页面状态、媒体播放、上游服务。
>
> 坐标是 **1200×2670（红米 24129PN74C / Android 17）** 实测值，换机型要重新量（见第 2 节）。

---

## 1. 前置检查

```bash
export PATH="/c/Android/platform-tools:$PATH"

adb devices            # 必须是 device，不能是 unauthorized / offline
adb shell wm size      # 记下分辨率，换机型时对照
adb shell pm list packages | grep love   # 确认 App 已装：cn.iepose.lovespace
```

`unauthorized` 说明手机上的「允许 USB 调试」弹窗还没点，解锁手机点允许。

**先确认线上版本**，避免验了半天是旧包：

```bash
curl -s http://192.168.31.95:1314/api/status | python -c "import json,sys;d=json.load(sys.stdin);print(d['version'],d['build'])"
```

## 2. 坐标怎么来

**`screencap` 出来的就是屏幕原图，图上坐标 = `input tap` 坐标，不需要任何换算。**

验证过一次就够了，别信「截图被缩放过」这种直觉：

```bash
adb -d exec-out screencap -p > /tmp/_chk.png
python -c "from PIL import Image; print(Image.open('/tmp/_chk.png').size)"   # (1200, 2670)
adb shell wm size                                                          # Physical size: 1200x2670
```

两者一致 → 1:1。所以第 4 节表里的坐标，全是在这张原图上量的，可以直接粘进 `input tap`。

**换机型**：`wm size` 拿到新的宽高，截图量出目标控件位置，直接填——同样不用换算。
只有一点要注意：坐标是**物理像素**，若 `wm size` 的 `Physical size` 与 `Override size` 不同（改过 `wm density`/`wm size`），以 Override 为准。

**取不准就迭代一次**：`input tap` → `screencap` → 看图确认落点。比反复猜快。

## 3. 冷启动

最关键的一步。五个 bundle 全部要加载、`boot()` 要跑完，任何加载期错误（函数没定义、
顺序错了）会在这里白屏。

```bash
adb logcat -c
adb shell am force-stop cn.iepose.lovespace
adb shell am start -n cn.iepose.lovespace/.MainActivity
sleep 14
adb logcat -d | grep -iE "net::ERR|CONNECTION_REFUSED" | head
adb exec-out screencap -p > /tmp/boot.png
```

**期望**：截图是首页（天数卡片 + 心情 + 纪念日倒计时），不是白屏、不是恢复页、不是登录页。

> ⚠️ 抓不到 JS 错误不代表没有。见第 6 节。

## 4. 逐页验收

按顺序走，每步 tap 完 `sleep 2~5` 再截图。下表坐标可直接用。

| # | 操作 | 命令（设备坐标） | 期望看到 |
|---|---|---|---|
| 1 | 底部「我们」 | `input tap 1066 2499` | 生理期大卡在最上，下面是数据看板/回忆周报/共同年历… |
| 2 | 点「生理期」 | `input tap 595 719` | **当前阶段 + 周期第 N 天 + 平均周期/经期/记录天数**；有历史数据时会出「有几点需要留意」 |
| 3 | 返回 | `input tap 124 203` | 回到「我们」 |
| 4 | 底部「首页」→ 下滑 | `input tap 94 2499` → `input swipe 600 2100 600 700 300` ×2 | 底部出现「我们的歌」卡片和「歌单 →」 |
| 5 | 点「歌单 →」 | `input tap 992 2254` | 「共同歌单」标题 + 歌曲卡片 |
| 6 | 点播放 | `input tap 183 1292` | **时间从 `0:00/0:00` 变成 `0:03/4:30` 这类真实时长**，按钮变暂停 |
| 7 | 顶栏聊天图标 | `input tap 734 206` | 私聊页，消息气泡和「一起看视频」邀请卡都渲染出来 |
| 8 | 点邀请卡 | `input tap 744 1537` | 一起看放映页：选片源按钮 + 上次选的剧集状态 + 底部输入框 |
| 9 | 点「选片源」 | `input tap 1029 208` | 「选一部一起看」，相册视频带缩略图 |
| 10 | 切「在线片源」 | `input tap 893 399` | 17 个组件卡片（带字标）+ 底部 Capy 服务地址；若无内容看第 7 节 |
| 11 | 收尾 | `input tap 850 2493` | 弹窗关闭，回到放映页 |

**判断标准**：每一步截图里有该页的标志性元素、没有空白、没有「加载中」卡住。
任一步白屏或控制台报错，先怀疑拆文件时漏了跨文件引用（见第 6 节）。

## 5. 每版必看的三处

这三个地方最容易在重构后被静默搞坏，且冒烟覆盖不到：

1. **生理期页**：有历史数据才渲染周期卡和提醒。空库走的是「开始记录」分支。
2. **歌单页播放**：`0:00/0:00` 且点了没反应 = 音频没加载；能走时间 = 媒体链路正常。
3. **在线片源**：要真连上上游 `192.168.31.95:8788`。手机必须在同一局域网。

---

## 6. 已知限制（别浪费时间在这上面）

- **CDP 接管不通**：WebView 的 devtools socket（`@chrome_devtools_remote`）虽然存在，
  但 release 包没开 `setWebContentsDebuggingEnabled`，`/json` 恒返回空。
  所以没法用 Playwright 直连真机 DOM——别在这上面折腾，除非改原生代码。
- **logcat 里没有 JS 错误**：App 没实现 `onConsoleMessage`，`console.error` 和
  `Uncaught` 都不会进 logcat。logcat 只能看 `net::ERR_*`、媒体、崩溃。
  **页面正不正常只能靠截图判断。**
- 坐标是硬编码的，键盘弹起、字体缩放、横屏都会失效。不适合做 CI。

---

## 7. 排障

| 现象 | 先查什么 |
|---|---|
| 某页白屏 | 拆文件时漏了跨文件引用。函数引用在**调用时**才解析，静态检查抓不到 |
| 页面还是旧版 | 下拉刷新；或 `force-stop` 后重启。SW 从旧版本号升上来会重装一轮 |
| 在线片源空 | 手机不在同一 WiFi；上游 `192.168.31.95:8788` 挂了；或组件未勾选 |
| 播放器 `0:00/0:00` | 音频直链过期或 `/media/<id>` 404，看 logcat 的 `net::ERR` |
| 图片/视频缩略图空白 | 同上，`/media/` 是 `private, max-age=0`，每次都要回源 |
| 点不动 | 坐标偏了，重新截图量；注意弹窗会吃掉底部导航区 |
